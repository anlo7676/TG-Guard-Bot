## 本地验证

使用独立的 `_test` MySQL 数据库和模拟 Telegram 接口，不向真实群发送测试消息。完整验证包含 Go 测试、go vet、Web 行为测试、安装/管理/部署/发布脚本测试及 Windows 本地构建。Go 官方漏洞扫描未发现当前依赖的已知可达漏洞。

本机规则稳态基准（Ryzen 7 7840HS，Windows amd64）：默认规则约 66 微秒/次、48 B、1 次分配；额外 50 个不同正则约 72 微秒/次、2459 B、51 次分配。可用 `go test ./internal/rules -run '^$' -bench BenchmarkLocalRules -benchmem` 复现。该数据衡量本地规则计算，不能代表数据库吞吐或生产端到端延迟。

Linux CI 另执行真实 Redis、race、跨包覆盖率、SIGTERM 子进程测试、Compose 校验及源码镜像构建。预编译发布还需要实际下载附件构建运行镜像并检查程序启动入口。以对应提交的 Actions 结果为最终跨平台验收依据。

## 保留的边界

- Telegram 与 MySQL 之间没有分布式事务，请求已执行而响应丢失时，消息提示仍可能重复。代码保存意图及检查点来恢复，不能保证端到端严格一次执行。
- 到期禁言和欢迎语删除需要服务、网络及机器人权限正常。欢迎语写入数据库失败后立即尝试删除，删除再次失败时记录可检索的群 ID 和消息 ID；数据库与 Telegram 同时故障不能承诺自动清理成功。
- 20 次恢复耗尽保留证据并计入人工关注指标；管理员应检查处罚失败原因，修复后重新作出管理决定。
- 仍为单实例应用内并发，未实施多副本分布式租约，也未进行生产规模压测。网页独立管理员依旧拥有全局权限。
- 升级涉及旧用户名名单停用和 API revision，操作步骤见 [安全与升级说明](security-and-upgrade.md)。
