# v1.9.0 安全与可靠性升级

## 后台登录与撤权

`ADMIN_API_TOKEN` 是后台恢复凭据，操作者 ID 为 0。登录后在「机器人管理员」添加 Telegram ID，再生成该管理员的独立后台登录密钥。独立密钥只显示一次，数据库仅保存高熵随机密钥的 SHA-256，不保存明文。请通过安全渠道分发。

独立管理员的网页操作以对应 ID 写入审计。删除管理员、更换或撤销其独立密钥，立即使该凭据、会话及登录票据失效；重新添加同一 ID 不会恢复旧密钥。只有使用恢复凭据登录的用户能签发独立密钥及退出全部后台会话。

会话和票据绑定恢复密钥指纹、独立凭据及全局撤销版本。更换 `ADMIN_API_TOKEN` 并重启后，旧会话和旧票据不能继续使用。请保持独立的 `SETTINGS_ENCRYPTION_KEY` 不变，避免更换登录凭据影响已加密设置的解密。

目前所有独立网页管理员仍有全局管理权限，不能将凭据发给只应管理一个群的成员。群管理员继续使用 Bot 私聊群设置，其权限由 Telegram 和群授权共同检查。

## HTTPS 后台

提供 `compose.https.yaml` 和 `deploy/Caddyfile`，要求 Compose 2.24.4 或更新版本。将域名解析到服务器，允许 TCP 80/443；80 用于证书签发及跳转。先在后台将入口地址设置为 `https://你的域名`，随后在 `.env` 增加：

```dotenv
PANEL_DOMAIN=guard.example.com
PANEL_BIND=127.0.0.1
COMPOSE_FILE=compose.yaml:compose.https.yaml
```

运行 `bash scripts/deploy.sh`，然后访问自己的 HTTPS 域名。Caddy 自动管理证书；应用的 8080 仍只绑定回环地址。`.env` 的 `COMPOSE_FILE` 会让后续管理菜单更新沿用 HTTPS 配置。此多文件路径写法用于 Linux。不要将示例域名原样用于部署。

HTTPS 模板为 Caddy 固定内部 IP，只信任该地址提供的转发头，避免所有访问者共享登录限额。默认子网 `172.31.249.0/24`、代理 IP `172.31.249.2`；与现有网络冲突时同时设置 `TG_NETWORK_SUBNET` 和该网段内的 `TG_PROXY_IP`。自行接入代理时设置 `TRUSTED_PROXY_CIDRS`，仅填写实际代理的地址范围，不要信任整个公网。直接访问者伪造的转发头不会参与限流地址判断。

AI 默认要求 HTTPS。受信任的本机或内网 HTTP 模型可在 AI 配置中显式开启「允许 HTTP 内网接口」；环境初始配置对应 `AI_ALLOW_INSECURE_HTTP=true`。旧版本保存的 HTTP 接口若未显式允许，升级后暂停 AI，后台仍可登录修改；不会偷偷通过明文发送 Key。

Compose 的数据库位于内部网络且没有公开端口。跨主机连接时，MySQL 应使用驱动支持的 TLS DSN，并通过受保护网络或 TLS 隧道连接 Redis；默认 Redis 客户端不适用于裸公网明文连接。

## 验证、处罚与恢复

权限操作先登记接管意图和授权版本，验证原状态保留。Telegram 返回成功后，再核对授权并原子提交处罚与验证状态。撤权发生在请求期间时保留补偿任务；不会覆盖撤权结果，也不会批量撤销历史已完成的处罚。解除封禁不会取消仍在进行的入群验证。

首次动作明确遭到 400/403 拒绝、且没有前序效果或不确定请求时，终止处罚。已删除消息、已完成权限动作或仅通知失败时继续恢复，不因通知失败丢失处罚记录。踢出分别记录封禁和解除封禁阶段。自动违规次数按已生效的删除或处罚统计，不再依赖提示发送成功。网络结果不明时暂缓答题恢复，由恢复扫描重试。

有限时禁言会持久登记到期解除任务。Telegram 请求临发送时为短时禁言预留两分钟安全期限，避免请求等待后剩余不足 30 秒被当作永久禁言；正常运行时由到期任务按原定时间解除。旧任务不会解除更新的处罚或新验证。恢复扫描及外部请求有延迟，停机时不能保证秒级精度；由管理员决定解除的广告复核禁言仍保持原有策略。

验证和欢迎语恢复使用最多 4 个并发工作槽，同群串行，每轮最多 20 秒；验证/删除单任务预算分别为 8/5 秒，单群每批最多 2 条。欢迎语清理遇到明确不可删除的 400 错误记录终止，403 或网络错误继续退避重试。五分钟是正常服务条件下的调度目标，停机、网络或 Telegram 权限故障期间无法保证。

`GET /health/ready` 返回 Telegram 状态、消息队列和 recovery 数据。关注 `verification_due_delay_seconds`、`welcome_due_delay_seconds`、`welcome_failed`、`punishment_pending`、`punishment_manual_attention` 和 `punishment_due_delay_seconds`。处罚恢复逐次退避，最多自动尝试 20 次，再保留为 pending 等待人工处理；检查处罚记录的失败阶段，修复权限后按需要重新发起管理操作。不要直接批量修改数据库为 done。消息待处理积压超过 5 分钟或 Telegram 持续不可用时，就绪状态失败。Docker 不会仅因为 unhealthy 自动重启容器，请配置外部监控。

## 升级与迁移

Go 升至 1.26.7，并升级 edwards25519 安全补丁。CI 执行真实 MySQL/Redis 集成测试、竞态检测、跨包覆盖率和官方漏洞扫描。

v1.9.0 新增 010 迁移，保存授权版本和处罚恢复步骤，启动时自动应用。升级后仅有用户名的旧黑白名单和可信名单不再生效，需根据确认过的 Telegram 数字 ID 重建；旧记录保留供检查和删除。系统设置增加 revision，旧 API 客户端需要先读取当前版本再提交，网页已适配。

Release 先以预发布状态上传程序，通过运行镜像构建及启动帮助检查后才标记为最新稳定版。安装器只跟随最新稳定版，不直接部署尚在验收的 main。更新启动失败时尝试恢复原代码及服务；不会自动回滚数据库。升级前备份 MySQL 和 `.env`，版本降级必须先核实数据库兼容性。

发布重跑会补传预发布附件，已稳定的附件保持不变；旧版本晚完成不会覆盖较新的 latest。服务健康后仅获取登录票据失败时保留已启动服务，可从管理菜单重新获取入口；HTTPS 部署显示域名地址。

历史 003–006 迁移中断后会核对已有字段定义再继续，定义冲突会拒绝启动并报告字段，不能以忽略所有 DDL 错误来掩盖损坏。
